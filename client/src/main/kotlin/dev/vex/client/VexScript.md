# 1. High-level overview

**What is VexScript?**
VexScript is a domain-specific scripting language for game server modulation and automation. It is:

* Readable and concise (Ruby-like `do/end`, optional parens).
* Explicit about mutability and resource usage (Rust-inspired `mut`, borrow hints).
* Scripting-first: `.vex` files are server-side scripts that can register events, define commands, and interact with in-game APIs.
* Host-aware: `Host.*` modules allow safe, auditable interaction with server files, network, and external services — gated by a capability model.
* Interop-ready: first-class bridges to **Lua** and **KotlinScript**, so script authors can reuse existing assets and logic.

Intended users: server admins, modders, world designers, and plugin authors.

---

# 2. Design goals & safety model

**Primary goals**

* *Ergonomics*: Make fast iteration and small-scripting frictionless.
* *Safety & auditability*: All host interactions are explicit, logged, and permissioned.
* *Extensibility*: Easy to add new API modules and external language bridges.
* *Kotlin-first implementation*: Parser generated by ANTLR, interpreter/runtime in Kotlin.

**Safety model highlights**

* Variables immutable by default; `mut` required for mutation.
* `Host.*` capability declarations required at top of script; server admin must grant them.
* Client-facing actions (file transfers, remote execution) require explicit player consent.
* All `Host.*` calls are logged and rate-limited.
* Scripts run in per-script sandboxes; a kill-switch exists for administrators.

# 4. Lexical elements (tokens)

* Comments:

    * Single-line: `# this is a comment`
    * Block: `=begin` ... `=end`
* Strings: double `"double #{interpolation}"` and single `'single'` (no interpolation)
* Symbols: `:symbol`, used for event and enum-like values
* Identifiers: `snake_case` recommended, may end with `?` or `!` (`is_alive?`, `save!`)
* Numbers: `123` (Int), `3.14` (Float)
* Arrays: `[1, 2, 3]`
* Hashes: `{ "key": "value", :symbol => 123 }` — both `:` and `=>` accepted
* Coordinates shorthand: `~`, `~5`, `~-3` (player-relative)
* Selectors: `@s`, `@playerName` (syntactic sugar for in-chat usage)

# 5. Syntax & idioms (Ruby-like with Rust/Crystal/Bash touches)

**Variable declaration**

* Immutable by default:

  ```vex
  x = 42
  ```
* Mutable:

  ```vex
  mut count = 0
  let mut total = 0   # `let` optional; both supported for readability
  ```

**Types (optional)** — Crystal-style annotation:

```vex
mut players: Array<Player> = Server.all_players()
fn greet(name: String) -> String do
  "Hey, #{name}"
end
```

**Functions & Methods**

* `fn` for top-level functions:

  ```vex
  fn add(a: Int, b: Int) -> Int do
    a + b
  end
  ```
* `def` for methods (sugar on types/objects)

  ```vex
  def Player#heal(amount: Int) do
    self.health += amount
  end
  ```

**Blocks**

* `do |args| ... end` or `{ |args| ... }`
* Blocks capture variables by immutable borrow by default; to mutate captured state annotate variable `mut` at declaration.

**Conditionals**

```vex
if health < 10
  heal(20)
elsif is_poisoned?
  cure()
else
  msg("Fine")
end
```

**Match (pattern-like)**

```vex
match damage.cause
| :lava => player.give_effect(:fire_resistance, duration: 10)
| :fall  => event.cancel()
| _      => Server.log("Unhandled: #{damage.cause}")
end
```

**Async & concurrency**

* `async fn` and `await` for host I/O
* `spawn` to start background tasks (cancellable)

```vex
async fn fetch(url: String) do
  resp = await Host.Http.get(url)
  resp.json()
end

spawn do
  data = await fetch("https://example/api")
  Server.broadcast("Status: #{data['status']}")
end
```

**Bash-like affordances**

* Script header shebang allowed: `#! /usr/bin/env vex` (ignored by parser but helpful for tooling)
* Single-line command style available for in-game shorthand (see Section 13).

# 6. Types, mutability & ownership model

**Core types**

* Primitives: `Int`, `Float`, `Bool`, `String`, `Symbol`, `Nil`
* Collections: `Array<T>`, `Hash<K,V>`
* Game objects: `Player`, `World`, `Entity`, `Item`, `Region`, `Coords`
* Resource types: `File`, `Socket`, `Stream`, `Task`

**Mutability**

* Default immutability (`x = ...`)
* `mut` marks mutable variables; `let mut` also accepted.
* Borrowing semantics exist at runtime:

    * `&T` — immutable borrow in method signatures (documented)
    * `&mut T` — mutable borrow required by mutating methods (runtime-checked)

**Ownership**

* Resources implement RAII-like `drop` semantics; explicit `close()` recommended.
* `with` helper ensures deterministic resource cleanup:

  ```vex
  with File.open(path, "w") do |f|
    f.write(data)
  end # f closed automatically
  ```

# 7. Control flow, functions, methods & `async`

**Function declaration**

```vex
fn compute(x: Int) -> Int do
  x * 2
end
```

**Method definition**

```vex
def Player#send_dm(msg: String) do
  self.msg(msg)
end
```

**Default parameter & named args**

```vex
fn greet(name: String = "Player", loud: Bool = false) do
  s = "Hello, #{name}"
  if loud then s.upcase() else s end
end
```

**Async example**

```vex
async fn fetch_json(url: String, timeout: Int = 10) do
  resp = await Host.Http.get(url, timeout: timeout)
  resp.json()
end
```

**Error handling**

* Use `try/catch` (in future versions) — currently use return-result patterns (`Result<T, E>` in stdlib) and explicit checks.

# 8. Blocks, closures & common DSL patterns

**Event handlers as first-class DSL**

```vex
Event.on(:player_join) do |ev|
  p = ev.player
  p.msg("Welcome, #{p.name}!")
end
```

**Iterators**

* `each` enumerators on collections:

```vex
Server.all_players().each do |p|
  p.msg("Server is restarting soon")
end
```

**Method-missing & DSL sugar**

* Language supports limited `method_missing`-style hooks for API-friendly DSLs (e.g., `World.fill from: a, to: b`) — implemented in runtime dispatch.

# 10. Host APIs (`Host.*`) — capability model & examples

**Core rule:** Any `Host.*` usage must be declared at the top of the script via `VEX-CAPABILITIES` header. Server admin grants capability when loading.

**Header example**

```vex
# VEX-CAPABILITIES: ["Host.Http", "Host.File"]
```

**Host.Http**

* `Host.Http.get(url: String, timeout: Int = 10) -> HttpResponse`
* TLS-only by default, logged, rate-limited
* Returns a response object with `status`, `text()`, `json()`, `headers`

**Host.File**

* `File.open(path, mode)` with sandboxing: default accessible directory `server/sandbox/`
* Sanitized paths; admin may allow broader access per capability grant

**Host.Net & Host.WebSocket**

* Raw sockets restricted; prefer `Host.Http` and `Host.WebSocket` unless admin explicitly allows `Host.Net`
* All outbound addresses whitelistable

**Host.Shell**

* Disabled by default — only for audited, trusted scripts. Avoid if possible.

**Client interactions**

* `Client.request_permission(player, scope: Symbol, reason: String)` — returns Bool
* `Client.send_file(player, path)` — only after permission

**Examples**

Filesystem backup:

```vex
# VEX-CAPABILITIES: ["Host.File"]
Server.run_repeating(interval: 3600) do
  with File.open(File.join(Server.sandbox_dir(), "backups.json"), "w") do |f|
    f.write(Server.player_list().to_json())
  end
end
```

HTTP fetch:

```vex
# VEX-CAPABILITIES: ["Host.Http"]
async fn check(url: String) do
  resp = await Host.Http.get(url)
  if resp.status == 200
    Server.log("OK: #{url}")
  else
    Server.log("Bad: #{url} => #{resp.status}")
  end
end
spawn do await check("https://status.example.com") end
```

# 11. Event system (`Event`) — lifecycle & handlers

**Only available in `.vex` files** (server-loaded scripts). The `Event` API provides:

* `Event.on(symbol, &block)` — subscribe
* `Event.once(symbol, &block)` — one-shot
* `Event.off(handle)` — remove handler
* Event objects contain typed properties (e.g., `PlayerDamageEvent.player`, `PlayerDamageEvent.cause`, `event.cancel()`)

**Example — cancel lava damage**

```vex
Event.on(:player_damage) do |event|
  if event.cause == :lava
    event.player.give_effect(:fire_resistance, duration: 10)
    event.cancel()
  end
end
```

**Handler lifecycle**

* On load: scripts register handlers
* On unload: handlers are removed, tasks cancelled, resources dropped
* Admins can hot-reload scripts; runtime enforces safety checks on reload

# 12. Interoperability: Lua + KotlinScript bridges

**Lua bridge (LuaJ)**

* `Lua.doString(luaCode: String)` — executes Lua sandboxed; host API exposure optional. Use for existing Lua logic.
* Data interchange: convert VexScript primitives ↔ Lua primitives. Complex objects mapped via wrapper proxies.

**KotlinScript bridge (Kotlin scripting host)**

* `KotlinScript.eval(kotlinCode: String)` — executes Kotlin script with a configured evaluation environment.
* The bridge provides a `game` object into script scope to access `Server`, `World`, etc., as safe proxies.

**Security**

* Both bridges respect `VEX-CAPABILITIES` and are subject to the same sandboxing & logging.
* Avoid exposing full JVM environment to KotlinScript; pre-bind safe host APIs only.

**Examples**

```vex
# Run Lua
Lua.doString("print('hello from lua')")

# Run Kotlin snippet
KotlinScript.eval("println(\"Time: ${'$'}{java.time.Instant.now()}\")")
```

# 13. Direct in-chat API call shorthand

For quick single-line commands via in-game chat:

```
::MODULE::FUNCTION(ARG1, ARG2; kw: value)::
```

Examples:

```
::WORLD::SUMMON(ANIMAL_DEER, ~X, ~Y, ~Z; amount: 100)::
::PLAYER::MSG(Steve; "Hello from in-chat VexScript!")::
```

**Limitations**

* No `async`, no file or host interaction; limited to safe server/game functions.
* Rate-limited and permission-checked for abuse prevention.

# 14. File layout, build & Kotlin implementation notes

**Recommended repo layout**

```
vexscript/
├─ build.gradle.kts
├─ settings.gradle.kts
├─ grammar/VexScript.g4
├─ src/main/kotlin/com/gemini/vexscript/
│  ├─ Main.kt
│  ├─ parser/           // generated ANTLR Java classes
│  ├─ ast/
│  ├─ runtime/
│  ├─ integrations/
│  └─ api/
└─ scripts/             // .vex files
```

**Build**

* Use Gradle with ANTLR plugin to generate parser (`org.antlr:antlr4`).
* Implement `AstBuilderVisitor` → AST nodes (`ast/`).
* Interpreter in `runtime/Interpreter.kt` that evaluates AST (directly or via bytecode).
* Bridges in `integrations/` (Lua, KotlinScript).
* All host modules must consult `CapabilityManager` before exposing operations.

**Notes**

* Kotlin is the runtime language; ANTLR produces Java classes, interoperable with Kotlin.
* Consider compiling hot paths to JVM bytecode later for performance.
* Provide REPL support for rapid testing (optional).

# 15. Security checklist for server admins & auditors

* [ ] Require script signatures for untrusted sources.
* [ ] Use `VEX-CAPABILITIES` header review policy.
* [ ] Sandbox `Host.*` with directory whitelists and network whitelists.
* [ ] Always prompt players for client-side actions — require consent.
* [ ] Log all `Host.*` calls with timestamp, origin script, and result.
* [ ] Rate-limit outbound network & CPU-heavy operations.
* [ ] Provide hot-kill switch for misbehaving scripts.
* [ ] Audit `KotlinScript` evaluation environment — restrict classpath.

# 18. Appendix A — grammar excerpts & ANTLR notes

A concise grammar excerpt (informal):

```
program        ::= statement*
statement      ::= var_decl | fn_decl | def_decl | event_decl | expr
var_decl       ::= ("let" | "mut")? "mut"? IDENT (":" TYPE)? "=" expr
fn_decl        ::= ("async")? "fn" IDENT "(" param* ")" ("->" TYPE)? block
def_decl       ::= "def" (RECEIVER ".")? IDENT "(" param* ")" block
event_decl     ::= "Event.on" "(" SYMBOL ")" block
block          ::= "do" ("|" params "|")? statements "end" | "{" statements "}"
expr           ::= assignment | logic
assignment     ::= IDENT (= | += | ...) expr
call           ::= primary ( "." IDENT | "(" args ")" | "[" expr "]")*
```

**ANTLR**

* Provide `VexScript.g4` (see prior deliverable) as grammar input.
* Generate Java parser with Gradle `antlr` plugin; call from Kotlin.
* Implement `AstBuilderVisitor` to walk parse tree → AST.
